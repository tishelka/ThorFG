# Проверка на AYN Thor Pro

## Проверка управления Decky после замены выпадающих меню

Владелец подтвердил, что ThorFG устанавливается, открывается и обновляет данные.
DropdownItem открывал меню, но выбор не работал ни кнопкой A, ни касанием.
В исправленном UI все семь DropdownItem заменены обычными ButtonItem с onClick:

1. Нажимайте «Раздел»: Обзор → Игры → Диагностика → Runtime → Обзор.
   Кнопка показывает текущий раздел, подпись — следующий.
2. Нажмите «Язык» дважды: Русский → English → Русский; раздел сохраняется.
3. В «Игры» откройте выбор игры: варианты — отдельные кнопки, по 20 на страницу,
   с поиском, предыдущей/следующей страницей и кнопкой «Назад к разделу».
4. Проверьте выбор EXE, runtime профиля и слота runtime таким же списком.
   Множитель переключается отдельной кнопкой ×2 → ×3 → ×4 → ×2, если доступен
   режим редактирования. При read-only блокировка ожидаема; не обходите её.
5. Повторите навигацию и выбор кнопкой A и касанием. Не нажимайте «Сохранить профиль»,
   «Активировать» или активные диагностические тесты для проверки одного управления.

Выбор меняет только локальное React-состояние до отдельного сохранения/активации.
Автоматические тесты запускают настоящий React и DOM с заглушками Decky/RPC;
они проверяют onClick и состояние, но не реальный ввод Steam. **Проверка управления
на Thor остаётся за владельцем консоли.** Backend и ARM64 runtime этой правкой не меняются.

Для текущего устройства с готовой build-llvm начните с
[обновления и восстановления существующей сборки](THOR_REAL_DEVICE_PROGRESS_RU.md).
Там зафиксированы переданные владельцем успешные ARM64 build/CDLL/loader insertion
и ещё не выполненные cube/FG проверки. Контрольные точки ниже — общий протокол;
повторная компиляция перед упаковкой существующей сборки не требуется.

`python3 scripts/device_probe.py` по умолчанию только читает файлы: показывает build,
bundle, slot, activation, SHA и архитектуры чужих слоёв. Активные режимы запускаются
отдельно: `--mode host-load`, `--mode loader`, `--mode cube`, все с тайм-аутом.
В Decky кнопки host load/изолированного loader доступны отдельно от просмотра статуса.
Сохранение профилей/активация при чужих менеджерах остаются заблокированными.

Статус Hardware Verified может появиться только после вашего реального теста на Thor.
Сейчас он false. Загрузка JS, сохранение TOML и обнаружение слоя сами по себе не подтверждают FG.

## Контрольная точка 1: сведения без установки

Откройте Konsole в ArmadaOS. Если SSH уже включён, подключитесь из Windows PowerShell:

```powershell
ssh USER@THOR_IP
```

USER/IP возьмите в настройках вашей консоли. При первом подключении сверьте fingerprint
с устройством. Не используйте предположения о заводском пароле; если он стандартный,
смените его командой `passwd` в Konsole и не присылайте пароль в чат.
Если SSH ещё не включён, используйте локальную Konsole: ThorFG не меняет настройки SSH.

**Konsole или SSH, корень скопированного проекта:**

```bash
cd "$HOME/thorfg"
bash scripts/collect-device.sh
```

Пришлите этот короткий вывод перед сборкой/активацией. Он не меняет систему и не читает
Steam токены, cmdline или environment процессов.

## Контрольная точка 2: установить и проверить loader

Выполните безопасный сценарий из руководства выше или BUILD_RU.md и INSTALL_RU.md
для первой установки. Не активируйте второй слой при существующем ArmadaLSFG.
В Game Mode откройте боковое меню Decky,
выберите ThorFG → Диагностика → Проверить Vulkan Loader.
Отсутствие vulkaninfo означает «неизвестно», а не успешную проверку.
При ошибке сохраните отчёт. В частности, vkCreateSwapchainKHR в vulkaninfo не
доказывает несовместимость GPU; cube с реальным swapchain остаётся отдельным тестом.

**Терминал ArmadaOS, вне контейнера:**

```bash
cd "$HOME/thorfg"
python3 scripts/thorfg.py diagnose --export
```

Обезличенный файл: `~/.config/thorfg/reports/diagnostic.txt` (либо XDG_CONFIG_HOME).
В нём намеренно нет персональных путей, названий игр и сырых журналов.
Терминальный вывод diagnose подробнее и содержит локальные настройки — перед отправкой
его целиком проверьте содержимое сами.

## Контрольная точка 3: одна игра

Persona 3 Reload подходит, если уже установлена и нормально запускается без ThorFG.
Naruto Storm 2 не является обязательной FG-целью: у вас она уже работает примерно в 60 FPS.

1. Запустите игру с выключенным профилем ThorFG. Запишите базовые FPS/frametime и настройки.
2. В Diagnostics получите процессы. Сверьте EXE реальной игры с кандидатом из библиотеки:
   launcher.exe может не быть нужным процессом. Суффиксы путей чувствительны к регистру.
3. Завершите игру. В «Игры» выберите её, укажите процесс, активный runtime, множитель x2,
   Flow Scale 0.5, Performance Mode ON, включите профиль и сохраните.
4. Запустите тот же сценарий и нажмите «Показать процессы игры». `layer_mapped=true` для PID
   игры — свидетельство маппинга библиотеки; это ещё не свидетельство генерации кадров.
5. Проверьте, что исходный и выводимый FPS измеряются раздельно достоверным инструментом.
   Если доступен только один счётчик, пометьте выводимый FPS «не измерен». Счётчик compositor
   может считать кадры интерфейса или игры без отделения синтетических кадров.
6. Повторите одну сцену с одинаковым лимитом/настройками. Запишите ghosting, UI-артефакты,
   frametime, загрузку GPU, нагрев, задержку управления и стабильность.
7. Выключите профиль, завершите игру и снова запустите. Обычный запуск должен восстановиться.

Менять профиль/множитель на лету во время первого теста не нужно. У upstream есть
hot reload некоторых полей, но удаление профиля требует swapchain recreation/перезапуска.
Цель x2 не гарантирует удвоение FPS: генерация отнимает часть GPU-времени.

## Сведения для протокола

Сохраните копию `examples/device-test-record.md` и заполните Armada build, Mesa/Turnip,
FEX, Proton, GPU, commit/SHA-256 runtime, DLL-ветку Steam, параметры, исходный FPS,
выводимый FPS (если измерен), frametime, артефакты и результат обратного отключения.
Версии FEX/Proton берите из **фактического выбранного compatibility tool**: системный FEX
может отличаться от того, который использует конкретная версия Proton.

Если слой маппится только в gamescope, исследуйте Vulkan thunk/rootfs выбранного Proton;
не устанавливайте x86-библиотеки наугад. Не меняйте глобальные Launch Options и драйвер.

## Отключение и восстановление

Сначала выключите профиль и завершите игру. Если UI недоступен, выполните:

```bash
cd "$HOME/thorfg"
python3 scripts/thorfg.py uninstall
```

Это снимает регистрацию собственного слоя и выключает наши профили.
Для восстановления последней операции используйте ROLLBACK_RU.md.
Если повреждён TOML или есть конфликт с чужим менеджером, автоматическая операция остановится,
чтобы не потерять сторонние данные. Разберите причину по TROUBLESHOOTING_RU.md.
